# PDD Parser - 拼多多商品采集与电商图片编辑工具

> 一站式拼多多商品数据采集 + AI 图片编辑 + 多平台文案改写的电商运营工具

## dev 分支与 1.4.0

本文对应 `dev` 开发分支，扩展版本为 **1.4.0**。主要更新：

- 默认仅启动本地管理后台，商品页由用户自行打开。
- 详情数据改为“读取预览 → 核对 → 确认保存”；列表自动记录默认关闭。
- 新增异常诊断中心、逐字段／SKU 来源记录和人工编辑保护。
- 统一价格单位与 SKU 事务更新，修复零库存、断线同步、导出和图片读取问题。
- 增加离线回归测试、Windows CI、依赖锁文件和源码白名单发布工具。

`dev` 是开发验证分支。现有测试使用离线样例与模拟浏览器 API，不能作为真实平台兼容性或账号免封的证明。

## 功能特性

### 数据采集

- **预览确认保存** - 用户打开商品详情页，点击“读取并预览当前商品”，核对字段后明确“确认保存”才入库
- **异常诊断中心** - 区分页面读取、预览确认、本地同步、图片、导入与导出错误，记录时间和处理建议
- **字段溯源** - 逐字段及 SKU 记录原始值、规范值、来源位置、观测时间与解析版本；人工编辑值与最新观测值分别展示
- **列表记录可选** - 店铺 / 搜索列表自动记录默认关闭；显式开启后只记录当前可见且可识别的商品卡片
- **明确单位** - 按字段定义转换价格的分/元，统一 SKU 规格；缺失库存保留为未知，售罄保留为 0
- **可靠同步** - 扩展后台持久化待传队列，后端确认成功后计数；后端离线时保留已接收数据
- **访问限制暂停** - 手动保存时识别可见验证提示或浏览器可提供的导航受限状态；下载遇到受限响应也会停止相关任务，人工检查后恢复
- **后台管理** - Web 管理界面，支持搜索、分页、分组筛选、标签筛选

### AI 图片编辑器

| 功能 | 说明 |
|------|------|
| 标签系统 | 12 种电商预设标签（7天无理由/包邮/新品上市等），支持拖拽、缩放、双击编辑、实时预览 |
| 滤镜 | 清新/复古/高对比/暖色/冷色/黑白等预设，一键应用 |
| 调色 | 亮度/对比度/饱和度滑块实时预览 |
| 裁剪 | 框选区域自由裁剪 |
| 变换 | 左旋/右旋/水平翻转/垂直翻转/缩放/平移 |
| 水印 | 自定义文字/颜色/字号/透明度，位置可拖拽 |
| 换底色 | 纯色/渐变填充，适配白底图需求 |
| 平台适配 | 一键设为拼多多/淘宝/抖音/小红书标准尺寸 |
| 分辨率 | 8 种电商常用分辨率（512x512 ~ 1920x1080） |
| 导出 | PNG/JPEG/WEBP 格式，可调质量 (10-100%) 和缩放 (25-200%) |

### AI 文案生成

- **智能改写** - 基于 OpenAI 兼容 API，自动改写商品标题、卖点、描述
- **多平台风格** - 适配淘宝/抖音/拼多多/小红书等不同平台的文案风格
- **批量生成** - 一次生成标题、副标题、卖点、详情全套文案

### 数据导出

- JSON / CSV / Excel / TXT 四种格式
- TXT 图文包包含商品信息 + 实际图片打包
- 支持批量导出 AI 生成图片

## 快速开始

### 环境要求

- Python 3.12+
- Chrome/Edge 120+
- Node.js 24（仅开发构建需要）

### 源码安装（Windows PowerShell）

```powershell
# 克隆项目
git clone --branch dev https://github.com/1tgbh/pdd-parser.git
cd pdd-parser

# 建立独立的 Python 环境并安装锁定依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r pdd_proxy/requirements-lock.txt
```

仓库提供 `pdd_proxy/frontend/dist/` 静态构建产物，可直接启动。需要前端开发或重新构建时执行：

```powershell
# 安装前端依赖并构建
cd frontend
npm ci
npm run build
# 构建结果直接写入 pdd_proxy/frontend/dist/
cd ..
```

### 启动

```powershell
# 启动 Web 后台（默认手动模式，仅自动打开本地后台）
.\.venv\Scripts\python.exe pdd_proxy/start.py
```

便携版目录已有 `python/python.exe` 时，可双击 `start.bat`。默认扩展模式无需管理员权限、系统代理或根证书。

```powershell
# 可选：先安装代理依赖，并按系统要求安装自己生成的 CA 证书
.\.venv\Scripts\python.exe -m pip install -r pdd_proxy/requirements-proxy.txt
# 在 Windows 上通过项目根目录的 install_cert.bat 安装证书
.\.venv\Scripts\python.exe pdd_proxy/start.py --proxy
```

macOS/Linux 可使用 `.venv/bin/python` 运行同一后端入口；本分支的自动化运行环境以 Windows / Python 3.12 为准。

启动后：

1. 首次使用在 Chrome/Edge 的 `chrome://extensions` 开启开发者模式，
   加载本仓库 `extension/` 目录（只需一次）
2. 启动后只会自动打开 `http://127.0.0.1:5000` 管理后台
3. 用户自行打开拼多多商品详情页，等待商品信息显示
4. 点击浏览器工具栏中的扩展图标，点击“读取并预览当前商品”
5. 在预览中核对商品、原链接、读取时间、价格、图片数量和 SKU；未知字段会明确标识
6. 点击“确认保存”加入本地同步队列，或“取消预览”放弃；确认前商品不会入库
7. 商品详情展开“字段来源与人工编辑保护”，查看逐字段和 SKU 的来源；后台“异常诊断”查看各阶段失败原因

升级到扩展 **1.4.0** 后，请重启后端、在扩展管理页重新加载 `extension/`，再刷新原有商品页面。
首次安装和从旧版升级时，列表自动记录均关闭；之后用户显式选择的列表开关会保留。
详情页始终由读取按钮与确认按钮触发，普通浏览、页面刷新、切换路由、打开扩展弹窗都不会自动保存详情。
当前预览保存在扩展本地，关闭弹窗后可继续核对；最多保留一个预览，10分钟后过期。页面刷新、目标切换、新预览或取消会使旧预览不可确认。
关闭商品标签页或重启整个浏览器会清理未确认预览；已经确认的待传队列仍保留。
确认保存只发送预览快照，不重新执行商品采集；实际读取时间和后端入库时间分别保存。预览只展示图片数量和链接，不为显示缩略图主动下载源站图片。

弹窗提示“已保存到本地待传队列”表示扩展已持久化接收数据，计数只统计成功入库的商品。
队列最多 100 条/约 6MB。后端离线时可以先保存，恢复连接后只重传已确认的数据。
旧版商品 / 列表待传数据保留为待确认项，可点击“同步已有待传”；关闭列表开关后，尚未同步的列表项也会暂停。
从1.3升级时，尚未入库的旧详情队列不会自动发送；需要明确确认同步，现有已入库商品保留。
“同步已有待传”只发送已存在的本地数据，不会重新读取或打开商品页面。“清理待传”会要求确认，不影响已入库商品。
验证提示会同时设置持续的本地暂停标记。清理队列、后端重启和连接恢复都不会解除它；人工检查平台页面后，在扩展中开启“允许保存 / 同步”明确恢复。

### 异常诊断与来源记录

- 扩展保存最近100条本地诊断，恢复后端连接后同步到诊断中心；后端最多保留最近500条。
- 诊断中的 HTTP 状态仅记录真实观察或本地响应，未观察时显示“未观测”；空 SKU 不作为封号证据。
- 图片已进入本地冷却期、源侧任务暂停等内部状态单独记录，不伪造为新的 HTTP 403/429。
- 图片访问失败只记录图片阶段和主机冷却，不将其自动升级为账号处罚；本地同步失败只重传已有数据。
- “标记已阅”仅管理诊断记录，不代表问题解决，也不会恢复暂停状态。
- 诊断仅使用固定类别、提示和脱敏来源，不保存 Cookie、令牌或原始页面状态。
- 字段来源记录从新采集／新编辑开始产生。历史商品没有逐字段来源时显示“历史来源未记录”，不补造来源时间。
- 人工标题、价格、图片与源侧快照分别保存。查看最新源价格不会覆盖人工销售价格；未知价格／库存不会抹掉已有有效 SKU 值。
- 本地导入标记为导入来源；API/结构化页面、DOM、计算值与人工修改在界面分开显示。来源说明是可核对的工程记录，不是平台授权证明。
- 导入的来源位置标为 `import.normalized.*`，表示文件解析后的规范字段；没有原字段证据时不推定其平台位置或原单位。

扩展权限说明：`activeTab` 用于用户点击扩展后临时访问当前标签页，`scripting` 用于运行一次只读提取函数，`storage/alarms` 用于本地队列及重传。
商品页不会常驻主世界采集脚本，也不再改写 `JSON.parse`、`fetch`、XHR 或页面路由函数。
可选列表脚本运行在隔离世界；开关关闭时不扫描列表、不安装 DOM 观察器。
脚本仅匹配店铺 / 搜索路径；开启列表记录时会尝试在当前列表页启用，若浏览器提示需要刷新，请刷新该列表页。

启动行为只打开本地后台，不自动打开平台登录页或商品页。后台图片预览、AI 编辑和导出仍可能按需读取图片，继续使用已有缓存和下载限流保护。

图文包导出通过一个共享后台任务队列执行，前端查询任务状态。相同的进行中任务会复用，图片使用公共缓存。
每个任务最多 500 件商品、5000 张图片；单图最多 20MB。受限或失败的图片列在压缩包的 `下载未完成.txt` 中。

## 工作原理

```
用户手动打开商品页 → 点击扩展“读取并预览当前商品”
  → background.js 验证当前标签页和暂停状态
  → 临时执行 inject.js，只读取当前商品的已加载字段
  → 复核页面未切换、商品 ID 一致
  → 扩展本地预览 → 用户明确确认
  → background.js 持久化队列 / 仅调用固定本地接口
  → Flask 校验来源、认证令牌、采集状态和字段
  → SQLite 事务更新商品和 SKU
  → 本地管理、图片编辑、导出
```

1. 扩展默认手动模式，无需系统代理或根证书，不主动补抓详情、刷新、翻页或点击 SKU。
2. 扩展只持有采集权限的本地令牌，管理后台使用独立会话；令牌不放入商品页面。
3. 商品价格/SKU在同一事务内更新，人工改价和编辑字段受到保护。
4. 历史趋势只记录实际观测数据。刷新本地记录不会抓取新价格；旧版没有真实观测时间的定时快照不作为新趋势数据。
5. MITM 是通过 `--proxy` 显式启动的独立备选模式，会自动记录已有的结构化响应；它不使用扩展的手动按钮流程。启动时同样只打开本地后台。

平台的风控判断不由本项目控制，无法承诺账号永不受限。SKU 缺失属于数据完整性问题，不作为封号判断。

## 常见问题

**Q: 浏览器提示证书错误？**
A: 以管理员身份运行 `install_cert.bat` 安装 CA 证书（证书文件不存在时脚本会自动生成）。macOS/Linux 可手动将 `pdd_proxy/certs/mitmproxy-ca-cert.pem` 导入系统受信任根证书。

**Q: 采集不到商品数据？**
A: 手动模式需要在商品详情页点击扩展里的“读取并预览当前商品”，核对后“确认保存”。检查诊断中心、暂停原因、缺失字段和待传数量。无法读取的字段保留为未知；出现验证提示时先人工检查平台页面，再恢复。

**Q: AI 功能报错？**
A: 在「设置」页面检查 API Key 是否配置正确，点击「测试」验证连通性。

**Q: 图片加载不出来？**
A: 管理后台通过带缓存的图片服务读取图片。403/429 会停止该主机的重复下载，冷却时间遵守服务端的 Retry-After；可以使用已有缓存或本地上传图片继续编辑。
